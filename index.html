00 · Before you start

바이브 코딩이 뭔가요

코드를 한 줄씩 직접 타이핑하는 대신, AI 코딩 에이전트(대표적으로 클로드 코드)에게 목표와 맥락을 말로 설명하고, 결과물을 확인·검증하며 함께 만들어가는 개발 방식입니다. 비유하자면, 직접 벽돌을 쌓는 대신 숙련된 시공팀에게 도면과 요구사항을 정확히 전달하고, 현장을 감독하는 역할에 가깝습니다. 도면(요구사항)을 얼마나 명확히 주느냐, 현장을 얼마나 잘 감독하느냐에 따라 결과물의 품질이 완전히 달라집니다.

# 왜 순서가 중요한가

말을 대충 던져도 처음엔 결과가 나옵니다. 하지만 작업이 커지면 맥락 전달, 작업 환경 설계, 반복 확인, 여러 작업 동시 진행이 차례로 필요해집니다. 순서를 건너뛰면 "왜 어제는 됐는데 오늘은 안 되지"를 계속 반복하게 됩니다.

# 이 페이지의 구성

① 용어사전 → ② 실제 설치 실습 (터미널 여는 법부터) → ③ 5단계 학습 순서(개념+실습 예시) → ④ 참고 자료 → ⑤ 자주 묻는 질문 → ⑥ 첫 주 체크리스트. 위에서부터 순서대로 읽으면 됩니다.

Glossary

먼저, 용어부터 — 딱 이만큼만 알면 됩니다

아래 8개 용어만 알아도 이 페이지 전체를 이해할 수 있습니다. 낯설어도 괜찮습니다, 한 번씩만 읽고 넘어가세요.

터미널 (Terminal)

글자만 입력해서 컴퓨터에 명령을 내리는 검은 화면. 마우스로 클릭하는 대신 문장을 쳐서 실행합니다. 클로드 코드는 기본적으로 이 화면에서 씁니다.

에이전트 (Agent)

단순히 질문에 답만 하는 게 아니라, 파일을 직접 읽고 고치고 명령을 실행하는 등 "행동까지 하는" AI. 클로드 코드가 대표적인 에이전트입니다.

프롬프트 (Prompt)

AI에게 주는 지시문. "이 함수에 에러 처리 추가해줘" 같은 한 문장도 프롬프트입니다.

컨텍스트 (Context)

AI가 답을 만들 때 참고하는 정보 전체. 지금까지의 대화, 읽은 파일, 프로젝트 설명 등이 모두 컨텍스트에 포함됩니다.

CLAUDE.md

프로젝트 맨 위에 놓아두는 메모 파일. "우리 팀은 이런 규칙을 씁니다"를 적어두면 클로드 코드가 매번 자동으로 참고합니다.

레포지토리 (Repository / 레포)

프로젝트 파일들을 담아두는 저장 공간. 깃허브(GitHub)에 만드는 "폴더"라고 생각하면 됩니다.

서브에이전트 (Subagent)

큰 작업을 나눠서 맡기는 보조 에이전트. 예를 들어 "코드 작성"과 "테스트 검증"을 서로 다른 서브에이전트에게 맡길 수 있습니다.

배포 (Deploy)

내가 만든 걸 다른 사람도 볼 수 있게 인터넷에 올리는 것. 이 페이지를 깃허브 페이지로 배포하면 링크 하나로 누구나 접속할 수 있습니다.

계정 준비

Claude.ai 계정(Pro, Max, Team, Enterprise 중 하나) 또는 Claude Console 계정이 필요합니다. 무료 플랜에는 클로드 코드가 포함되지 않으니, 회사에서 제공하는 계정이 있다면 그걸 사용하세요.

터미널 열기

맥(Mac)은 Spotlight(Cmd+Space)에서 "터미널"을 검색, 윈도우는 시작 메뉴에서 "PowerShell"을 검색해서 엽니다. 검은(또는 흰) 화면에 깜빡이는 커서만 있으면 잘 연 겁니다. 앞으로 이 페이지의 터미널 모드 명령어는 전부 이 창에 입력합니다.

Git Bash를 쓰셔도 됩니다 — 윈도우에 Git을 설치할 때 같이 깔리는 별도 터미널 프로그램인데, PowerShell과 다른 프로그램이지만 이 실습에는 똑같이 써도 무방합니다. 오히려 Git Bash를 쓰면 아래 설치 명령어를 PowerShell용이 아니라 macOS/Linux용 그대로 입력하면 됩니다. 아무 폴더에서 우클릭 → "Git Bash Here"로 열 수 있습니다.

클로드 코드 설치

운영체제와 터미널에 맞는 명령어 한 줄을 그대로 붙여넣고 엔터를 누르면 됩니다.

macOS / Linux / WSL / Git Bash

Windows (PowerShell)

claude --version

VS Code 확장 프로그램 설치

Learning path

5단계로 보는 학습 순서

2022년부터 2026년 현재까지, AI 코딩을 다루는 방식은 이렇게 진화해왔습니다. 이 순서 그대로 따라가면 됩니다 — 아래 단계를 건너뛰고 위 단계부터 시도하면 반드시 막힙니다.

01
2022–2023가장 먼저

프롬프트 엔지니어링

모델에게 "어떻게 말할 것인가"

AI와 대화하는 방법 자체를 익히는 단계입니다. 요청을 구체적으로 쓰기, 예시를 주기, 원하는 출력 형식을 명시하기, 단계별로 생각하게 시키기 같은 기본기가 여기 속합니다. 여기가 부실하면 다음 단계는 의미가 없습니다.

공식 가이드가 알려주는 패턴 4가지 — Claude Code 공식 문서 정리
  • 조건까지 같이 말하기 — "로그인 버그 고쳐줘" 대신 "로그인 화면에서 비밀번호를 틀리면 빈 화면만 뜨는 버그를 고쳐줘"처럼 어떤 상황인지까지 붙이기
  • 복잡한 일은 번호로 쪼개기 — "1. 사용자 정보 테이블 만들고 2. 조회/수정 API 만들고 3. 화면 만들어줘"처럼 순서를 먼저 정리해서 주면 결과가 훨씬 안정적
  • 고치기 전에 먼저 살펴보게 하기 — 바로 "고쳐줘"보다 "이 부분 구조를 먼저 분석해줘"로 시작하면, 엉뚱한 곳을 건드릴 확률이 줄어듦
  • 거꾸로 질문을 받기 — 큰 기능을 새로 만들 때는 "만들기 전에 나한테 궁금한 걸 먼저 질문해줘"라고 요청 — 놓치기 쉬운 예외 상황을 미리 짚어줌

  3. "단계별로 생각해서 알려줘"를 붙여보기 복잡한 요청 하나에 이 문구를 붙였을 때/안 붙였을 때 결과 차이 확인
    같은 세션에서, 아래 두 문장을 각각 /clear 후 입력
    A이 프로젝트에 회원가입 기능을 추가해줘
    B이 프로젝트에 회원가입 기능을 추가해줘. 어떤 파일을 왜 수정할 건지 단계별로 먼저 설명하고 시작해줘

    메모장 앱 또는 노션 등, 아무 텍스트 도구
✓ 준비 신호요청할 때 "무엇을, 어떤 형식으로, 어떤 조건과 함께" 원하는지를 자연스럽게 같이 쓰게 됐다면 다음 단계로 넘어갈 준비가 된 것입니다.

컨텍스트 엔지니어링

모델이 "무엇을 알고 있는가"

잘 말하는 것만으로는 부족합니다. 프로젝트 구조, 코딩 컨벤션(규칙), 이전 결정 사항 같은 맥락을 AI가 매번 다시 배우지 않도록 설계하는 단계입니다. 클로드 코드에서는 CLAUDE.md 파일이 이 역할을 합니다 — 프로젝트 루트(맨 위 폴더)에 넣어두면 세션마다 자동으로 읽힙니다.

# CLAUDE.md 예시 (프로젝트 최상위 폴더에 저장) # 우리 팀 프로젝트 안내 ## 이 프로젝트는 사내 문의 접수 웹페이지입니다. ## 지켜야 할 규칙 - 화면 문구는 반드시 존댓말로 작성 - 날짜 형식은 YYYY.MM.DD 로 통일 - 개인정보(이메일, 전화번호)는 로그에 남기지 않기 ## 자주 실수하는 부분 - 버튼 문구를 영어로 쓰지 말 것 (전부 한글)
CLAUDE.md, 사실은 3단 구조입니다 — Claude Code 공식 문서 정리
  • 회사 전체 규칙 → 프로젝트 규칙 → 개인 규칙 순으로 겹겹이 쌓입니다. 회사 전체 규칙(관리자가 배포)이 가장 먼저 적용되고, 그 위에 프로젝트 규칙(레포에 저장, 팀 전체 공유), 그 위에 개인 규칙(나만 적용, 개인 습관·단축키 등)이 얹힙니다.
  • 내가 쓰는 CLAUDE.md 말고도 "자동 메모리"가 따로 있습니다. 대화 중 "그거 아니고 이렇게 해줘"라고 고쳐주면, 클로드가 그 내용을 스스로 기억해뒀다가 다음에 반영합니다. CLAUDE.md는 내가 직접 쓰는 것, 자동 메모리는 클로드가 알아서 배우는 것으로 역할이 다릅니다.
  • 세션 중에 /memory라고 치면 지금 어떤 메모리 파일들이 실제로 로드돼 있는지 바로 확인할 수 있습니다. "왜 규칙을 안 지키지?" 싶을 때 가장 먼저 확인할 명령어입니다.
  • 파일이 너무 길어지면 오히려 방해가 됩니다. 매번 필요한 규칙만 남기고, 가끔 쓰는 절차(예: "배포할 때는 이 순서로")는 CLAUDE.md 대신 별도 기능(skill)으로 분리하는 걸 공식 문서도 권장합니다.
이렇게 공부하세요1~2시간
  1. 연습용 프로젝트 폴더에 CLAUDE.md 만들기 위 예시 그대로 복사해서 시작해도 됨 — 완벽하게 쓰려 하지 말고 일단 만들기
    그 폴더 맨 위(최상위)에 새 텍스트 파일을 만들고 이름을 정확히 CLAUDE.md로 저장 (윈도우 메모장은 기본적으로 .txt를 자동으로 붙이니, 저장할 때 파일 이름을 "CLAUDE.md"처럼 큰따옴표로 감싸서 저장하면 .txt가 안 붙습니다). 또는 세션 안에서 /init만 입력해도 클로드가 알아서 초안을 만들어줍니다 — 이 방법이 더 쉽습니다
  2. "프로젝트 배경 3줄 + 규칙 3~5개 + 자주 하는 실수 1~2개" 채우기 본인 업무/프로젝트에 맞게 실제 내용으로 교체
    방금 만든 CLAUDE.md 파일을 텍스트 편집기로 직접 수정
  3. 같은 질문을 CLAUDE.md 있을 때/없을 때로 각각 던져보기 차이를 메모해두기
    세션 안에서 먼저 그대로 질문 → 파일 탐색기(윈도우) 또는 Finder(맥)에서 CLAUDE.md 파일을 우클릭 → "이름 바꾸기"로 CLAUDE-off.md처럼 바꿔서 잠깐 숨긴 뒤 → 세션으로 돌아와 /clear → 같은 질문 다시 (끝나면 파일 이름 다시 CLAUDE.md로 되돌리기)
    >새 화면에 안내 문구 하나 써줘
  4. Awesome CLAUDE.md 템플릿 훑어보기 남들은 어떻게 쓰는지 참고만 하고, 내 CLAUDE.md에 항목 1~2개 더 추가
    웹 브라우저에서 아래 "공식 링크" 목록의 Awesome CLAUDE.md 링크
✓ 준비 신호매번 같은 설명을 반복하지 않고 "저번에 말한 대로 해줘"가 자연스럽게 통하면 다음 단계로 넘어갈 준비가 된 것입니다.

하네스 엔지니어링

에이전트를 둘러싼 "자율성과 통제 장치" 설계

에이전트가 스스로 파일을 읽고, 명령을 실행하고, 여러 단계를 이어가기 시작하면 이제 문제는 "무엇을 시킬까"가 아니라 "어디까지 맡기고 어떤 안전장치를 둘까"가 됩니다. 도구 연결, 자동 검증(Hook), 권한 통제, 작업 분담(서브에이전트) 등 실행 환경 전체를 설계하는 단계입니다.

# 예시: 코드를 저장할 때마다 자동으로 테스트를 돌리는 Hook "PostToolUse": "파일 저장 후 → npm test 자동 실행 → 실패하면 에이전트에게 결과 다시 알려주기"
서브에이전트 & Hook, 실제로는 이렇게 동작합니다 — Claude Code 공식 문서 정리
  • 서브에이전트는 대화창을 새로 하나 더 여는 것과 비슷합니다. 본래 대화와 별도로 독립된 컨텍스트를 가지므로, 큰 조사를 서브에이전트에게 시켜도 원래 대화가 지저분해지지 않습니다. .claude/agents/ 폴더에 마크다운 파일 하나로 정의합니다.
  • 이미 내장된 서브에이전트도 있습니다. 탐색 전용(Explore), 계획 전용(Plan) 같은 것들이 기본으로 딸려 있어서, 처음엔 직접 만들지 않아도 활용할 수 있습니다.
  • Hook은 "AI의 판단과 무관하게 확실히 실행"시키는 장치입니다. 대표적으로 두 가지만 알아도 충분합니다 — PreToolUse(행동하기 전에 가로채서 막을 수 있음, 예: 위험한 명령 차단), PostToolUse(행동이 끝난 후에 자동으로 포맷팅·검증). CLAUDE.md는 "이렇게 해줘"라는 부탁이지만, Hook은 지켜지지 않으면 아예 막아버리는 장치라는 점이 다릅니다.
  • 설정은 .claude/settings.json 파일 하나에 적습니다. 팀 전체가 지켜야 할 규칙은 레포에 커밋해서 공유하고, 개인적인 자동화는 내 컴퓨터에만 남겨두는 식으로 나눠 씁니다.
이렇게 공부하세요반나절~하루
  1. Subagents 문서 읽고 "작업을 나눈다"는 감 잡기 코드 작성용/검증용처럼 역할을 나눠 맡기는 개념만 이해하면 충분
    웹 브라우저, 위 지식 박스만 읽어도 충분 (링크는 선택)
  2. 권한 모드 한 번 바꿔보기 "이건 자동으로 허용, 이건 매번 나한테 물어보게" 를 직접 체감해보기
    세션 안(> 줄)에서 Shift+Tab 키를 눌러보기 — 화면 아래쪽 모드 표시가 바뀌는 게 보임
    입력창 바로 아래줄, 모델 이름(예: Sonnet) 옆에 작은 글씨로 모드 이름이 적혀 있고, 그걸 클릭하면 목록이 뜹니다 (버전에 따라 위치가 조금 다를 수 있습니다)
    못 찾겠다면 — 세션 안에 그냥 "앞으로는 매번 물어보지 말고 어느 정도 알아서 진행해줘"라고 말로 요청해도 비슷하게 체감할 수 있습니다.
  3. 간단한 Hook 하나 걸어보기 메뉴를 뒤질 필요 없이, 말로 그대로 요청하는 게 가장 확실합니다
    세션 안(입력창)에서 아래 문장을 그대로 입력
    >파일을 저장할 때마다 자동으로 알려주는 Hook을 하나 만들어줘. 복잡한 거 말고 테스트용으로 간단한 걸로.
    클로드가 알아서 설정 파일을 만들고 어떻게 됐는지 설명까지 해줍니다. /hooks를 직접 입력해서 메뉴로 설정할 수도 있지만입력창 아래 "Customize" 메뉴에서 화면으로 설정할 수도 있지만, 처음에는 이렇게 말로 시키는 쪽이 훨씬 헤매지 않습니다.
  4. 작업 하나를 통째로 맡긴 것과, 단계별로 확인하며 진행한 것 비교 시간과 결과 품질 차이를 느껴보기
    같은 세션 안(> 줄)에서 자동 모드 vs 수동 모드로 각각 실행 (역시 Shift+Tab으로 전환)
    같은 세션에서, 위에서 찾은 모드를 바꿔가며 각각 실행 (못 찾았다면 앞 단계의 말로 요청하는 방법 그대로 사용)
✓ 준비 신호"이 작업은 통째로 맡겨도 되겠다"와 "이건 단계마다 확인해야겠다"를 스스로 구분해서 판단할 수 있으면 다음 단계로 넘어갈 준비가 된 것입니다.
왜 필요한가 — 같은 모델이라도 주변 환경 설계에 따라 결과 품질이 크게 달라집니다. 프롬프트를 아무리 고쳐도 안 되던 문제가, 권한 범위나 검증 단계를 손보면 해결되는 경우가 많습니다.

루프 엔지니어링

매번 프롬프트를 치는 대신 "스스로 도는 순환"을 설계

계획 → 실행 → 검증 → 재시도를 사람이 매번 개입하지 않아도 에이전트가 스스로 반복하게 만드는 단계입니다. 목표(예: "테스트를 모두 통과시켜라")만 던져주면 에이전트가 코드를 고치고, 테스트를 돌리고, 실패하면 원인을 보고 다시 고치는 흐름을 스스로 도는 것이 핵심입니다.

루프가 알아서 도는 걸 실제로 확인하는 법 — Claude Code 공식 문서 정리
  • Pro/Max/Team 요금제는 기본값이 이미 "자동 모드"입니다. 첫 세션 이후로는 매번 승인받지 않고, 별도의 검토 로직이 대신 확인하면서 대부분의 파일 수정·명령 실행을 스스로 진행합니다 — 이게 바로 "루프가 도는" 상태입니다.
  • Shift+Tab 키 하나로 "매번 저한테 물어보고 진행" ↔ "알아서 진행" 모드를 세션 중에 바로 바꿀 수 있습니다.
  • 입력창 아래 모드 드롭다운으로 Normal(매번 승인) / Auto(대부분 자동) / Plan(계획만 세움) / Edit automatically(전부 자동) 네 가지를 그때그때 바꿀 수 있습니다.
  • 추천 순서 — 처음 다뤄보는 프로젝트는 매번 확인받는 모드로 시작해서 에이전트가 어떻게 판단하는지 감을 잡고, 믿을 만하다 싶으면 자동 모드로 넘어가는 게 안전합니다.
이렇게 공부하세요하루
  1. "완료 기준"이 명확한 작업 하나 고르기 예: 체크리스트 5개 항목 전부 충족 / 정해진 형식대로 결과물 나오기
    종이나 메모장에 조건 5개를 먼저 글로 적어보기
  2. 그 기준을 그대로 목표로 던지기 기준을 조건으로 그대로 옮겨서 요청
    세션 안에서 입력
    >회원가입 폼에 아래 5가지를 모두 만족할 때까지 스스로 확인하고 고쳐줘: 1) 이메일 형식 검증 2) 비밀번호 8자 이상 3) 중복 이메일 차단 4) 에러 메시지 한글 표시 5) 성공 시 로그인 화면 이동
  3. 몇 번 반복했는지, 어디서 멈췄는지 관찰하기 과정을 지켜보면서 어떤 지점에서 판단이 갈렸는지 메모
    같은 세션 화면을 그대로 지켜보기
  4. 기준을 모호하게 줬을 때와 비교 결과 안정성 차이 확인
    /clear 후, 이번엔 "회원가입 폼 잘 만들어줘"처럼 조건 없이 요청해서 비교
✓ 준비 신호"완료란 무엇인가"를 사람이 아니라 시스템이 판단할 수 있게 기준을 글로 명확히 쓸 수 있으면 다음 단계로 넘어갈 준비가 된 것입니다.
핵심 인사이트 — 이 단계에서 병목은 모델의 실력이 아니라 "무엇을 완료로 볼 것인가"를 판단하는 검증 기준입니다. 테스트, 체크리스트처럼 명확한 기준이 있어야 루프가 제대로 돕니다.

자주 묻는 질문

공식 링크들이 다 영어인데, 굳이 가서 봐야 하나요?
아니요, 꼭 가지 않아도 됩니다. 이 페이지의 각 단계에 있는 "공식 문서 정리" 박스에 핵심 내용을 이미 한국어로 옮겨뒀고, "실제로 설치해보기"의 명령어 표도 한국어입니다. 하루 쓰는 데 필요한 정도는 이 페이지 안에서 끝납니다.

그럼 아래 "공식 링크 바로가기"는 언제 쓰냐면 — ① 여기 요약에 없는 세부 옵션이 궁금할 때, ② 클로드 코드 버전이 업데이트돼서 최신 내용을 확인하고 싶을 때, 이 두 경우뿐입니다. 이때 영어가 걸림돌이면:
① 크롬 브라우저의 "한국어로 번역" 기능 켜고 보기 — 가장 빠름.
② 위 04번 자료 중 CC101(한국어 원작 가이드)로 먼저 감 잡기.
③ 링크를 복사해서 클로드에게 "이 문서 한국어로 요약해줘"라고 시켜보기 — 이것도 01단계(프롬프트 엔지니어링) 연습이 됩니다.

주의: 검색하다 보면 "Claude Code 문서 한국어 번역"을 자처하는 자료가 여럿 나오는데, 그중에는 공식 문서가 아니라 유출된 내부 소스코드를 분석한 비공식 자료를 번역한 것도 섞여 있습니다. 출처가 code.claude.com 또는 claude.com이 아니면 공식이 아니라는 뜻이니, "공식"이라는 표현만 보고 바로 신뢰하지 않는 게 안전합니다.
저는 개발 경험이 전혀 없는데, 시작해도 되나요?
네. 바이브 코딩의 요점은 "코드 문법을 외우는 것"이 아니라 "원하는 결과를 명확히 설명하고, 나온 결과가 맞는지 판단하는 것"입니다. 위 1~2단계(프롬프트·컨텍스트 엔지니어링)만 익혀도 실무에 바로 쓸 수 있습니다.
터미널이 무섭습니다. 꼭 써야 하나요?
클로드 코드는 터미널 외에도 데스크톱 앱, VS Code 같은 에디터, 웹 브라우저에서도 쓸 수 있습니다. 다만 이 로드맵의 설치 실습은 가장 기본이 되는 터미널 방식으로 안내했습니다 — 한 번 익숙해지면 오히려 제일 빠릅니다.
비용이 얼마나 드나요?
클로드 코드는 Claude.ai 구독(Pro/Max/Team/Enterprise) 또는 Console 계정(사용량 기반 결제)으로 이용할 수 있습니다. 정확한 요금은 계속 바뀌기 때문에, 이 페이지에 수치를 적기보다 claude.com 공식 요금 페이지를 확인하는 걸 추천합니다.
하네스·루프·그래프 엔지니어링, 다 외워야 하나요?
아니요. 순서대로 "존재를 알고 필요할 때 찾아볼 수 있는" 정도면 충분합니다. 실무에서 매일 쓰는 건 1~2단계이고, 3단계(하네스)부터는 프로젝트가 복잡해질 때 필요해집니다.
이 페이지 내용은 언제 기준인가요?
2026년 8월 기준으로 조사했습니다. 특히 5단계(그래프 엔지니어링)는 용어 자체가 최근에 나와서 계속 바뀔 수 있으니, 링크된 원문을 주기적으로 다시 확인하는 걸 추천합니다.

Hands-on · 마지막 단계

GitHub에 배포하기 (10분)

지금까지 만든 index.html 파일을 인터넷에 공개하는 마지막 단계입니다. 여기서 쓰는 GitHub는 앞서 설치한 Git Bash(터미널 프로그램)나 VS Code(에디터)와는 전혀 다른, 인터넷 웹사이트입니다 — 이 단계는 전부 브라우저에서 마우스 클릭으로 진행합니다.

시작 전에, 셋의 관계만 다시 확인 — 이름이 비슷해서 헷갈리기 쉬움
  • Git Bash — 내 컴퓨터 안의 터미널(명령어 입력 창) 프로그램
  • VS Code — 내 컴퓨터 안의 코드 편집기(에디터) 프로그램
  • GitHub — 인터넷에 있는 웹사이트. 파일을 올려서 공개하는 "온라인 창고" 역할. 오늘 할 일은 이것 하나뿐

GitHub 계정 만들기

이미 계정이 있다면 이 단계는 건너뛰세요. 없다면 아래 가입 페이지에서 이메일·비밀번호·아이디만 입력하면 무료로 만들어집니다.

브라우저에서 github.com/signup 접속

새 저장소(repository) 만들기

로그인한 상태에서 오른쪽 위 + 버튼 → New repository 클릭. 이름은 예를 들어 vibe-coding-roadmap. Public(공개)을 선택하세요 — GitHub Pages 무료 배포는 Public 저장소여야만 작동합니다. "Add a README file"은 체크하지 않아도 됩니다. 마지막으로 Create repository 클릭.

브라우저에서 github.com/new 접속 (로그인 필요)

index.html 파일 업로드

방금 만든 저장소 페이지에서 Add file → Upload files 클릭 → 가지고 있는 index.html을 그대로 끌어다 놓기 → 맨 아래 Commit changes 클릭.

파일 이름이 중요합니다 — 정확히 index.html이어야 GitHub Pages가 자동으로 이 파일을 첫 화면으로 인식합니다. 다른 이름으로 저장돼 있다면 업로드 전에 이름을 바꿔주세요.

GitHub Pages 켜기

저장소 상단 메뉴에서 Settings → 왼쪽 메뉴 Pages 클릭 → "Build and deployment"의 Branch를 main, 오른쪽 폴더는 /(root)로 선택 → Save. 1~2분 정도 기다립니다.

배포된 링크 확인

같은 Pages 화면 위쪽에 https://[아이디].github.io/vibe-coding-roadmap 형태의 링크가 뜹니다. 그 링크를 열어서 페이지가 잘 보이면 성공입니다 — 그 링크를 과제함에 제출하면 됩니다.
